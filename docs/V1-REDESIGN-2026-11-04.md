# Herald Voyages V1 implementation candidate

Implemented against `67464afb8d890c97b5157c4bfec01023ca5cb4bf`, on local branch `codex/herald-v1-20261104`. The November audit remains an immutable baseline under `docs/audits/2026-11-04/`. This document records the subsequent implementation; it does not certify the existing hosted deployment.

## Product changes

Home now has a geographic focal point using bundled Natural Earth geometry and the existing recorded-country engine, an explicit route into five workspaces, and practical Today/Tomorrow lists. The first useful travel item is checked within the initial viewport at 360/390 phone, 768 tablet, 1265×632 laptop and 1440 desktop. The map is optional: it loads after functional content, is omitted on narrow phones, and offers a fallback/retry without blocking travel records.

Atlas presents selected-country context alongside geography on wide screens, with a keyboard-accessible recorded-country list and predictable focus transfer. Phone stacks the context. Country history has one clear identity, visit readers, and links to explicitly named journeys and their date-overlapping accommodation. These links do not assign membership or assert presence from a similar name. Existing blue selection, timeline and map camera remain.

Shared readers open hotel, transport, country, note, dated location and saved-place details before explicit Edit. Readers retain source route/query/filter/scroll, support direct links and browser Back, restore focus even when a source row rerenders, and close on traveller/account identity changes. Calendar's existing Day Explorer remains intact. Saved-place relationships use source/saved IDs, never fuzzy name matching.

Saved places now have normalized name/address/country search, result counts, a clear action, bounded 40-row pages, and separate View/Manage actions. Transport's practical records precede its map; on phones the map is disclosed explicitly. Trips offer a date-scoped review of existing records before grouping. Overview/Daily itinerary tabs use conventional arrow/Home/End keyboard behavior and itinerary records can be read without entering an editor.

Statistics add year selection and contributing-record drill-down through the existing history engine. Manual year/undated visits retain their precision; future/tentative/cancelled travel, residence and country-definition rules are preserved. Lifetime insights remain available. Notes gain optional inclusive end dates and explicit one-day/undated overrides; Calendar, Home and itinerary share the existing range projection. Checklist sections can be renamed/reordered or removed with explicit item reassignment, preserving IDs, completions and unknown fields, with failed-save rollback.

## Visual behavior

`v1-experience.css` owns the new page composition and presentation roles. The existing calendar styles continue to own schedule lanes. Paper, ink, cloth red, map blue and warm gold carry the brand across Home, Calendar, Atlas, country pages, readers, Places and statistics. Calendar filters/display settings use native disclosures; reducing framing moved the tested desktop grid start from approximately 314px at audit baseline to 250px. This is fixture-specific, not a promise for every month/device. Country badges and accommodation turnover halves are unchanged.

Fine-pointer input can illuminate and gently shift the Home map, with slight button response. Scroll progress and modest entry transitions explain movement without trapping scrolling or withholding text. A trip's optional Journey chapters presents its actual linked country chronology, a progress line, real field notes and record links; it is labeled as chronology rather than route geometry. Photographs can gain saturation on interaction. Native readers/panels open with brief transitions and retain stable URLs and Back behavior.

Preferences provide a persisted motion switch, optional daytime/night theme on opening, and explicitly decorative Home-map golden light/rain/snow. Manual theme input overrides the schedule. System reduced motion takes precedence and all travel tasks work without effects. Decorative weather is visibly labeled and never presented as historical data. There is no autoplay audio. The optional physics scrapbook and sound library are not included in this candidate.

- **AUD-02/T09:** canonical LF release bytes, deterministic generated bundles, strict exact-byte manifest checks and complete release verifier. Hash checks and previous-complete-shell protections remain.
- **AUD-03:** the existing lazy itinerary test waits for rendered content; original assertions remain.
- **CAL-01:** partial range anchors survive month/year/Today navigation until explicit completion/cancel/context exit.
- **CAL-02:** one zoned resolver validates new/edited endpoint times, rejects DST gaps, requires an explicit repeated-hour occurrence and checks known chronology, including overnight/Date Line cases. Unknown zones stay uncertain. Historical read/import/export source fields remain unchanged. See `ZONED-TIMES.md`.

## Validation and limitations

The implementation report packaged with the source records the executed commands and results. Checks use fictional records, isolated browser contexts and mocked account APIs, with nonlocal requests blocked in the browser harness. No owner-account form was saved; no production SQL, Auth, email configuration or hosting change was made.

Local integrity success does not repair the currently published bytes: deployment is explicitly outside this task. After an authorized release, run `node scripts/verify-release.cjs https://YOUR-PUBLISHED-BASE/` and rehearse fresh/offline/upgrade behavior against those served bytes. See `RELEASE-INTEGRITY-2026-11-04.md` for isolated SQL and release evidence. Production grants/email/restore and manual NVDA/VoiceOver/real-device Safari acceptance remain operational verification gates. The isolated supplied-SQL check confirms a same-owner direct-write bypass of RPC validation; this candidate does not alter schemas/grants because those changes were excluded by the brief. A separate reviewed write-boundary change is required if the deployed setup matches that source contract.

No complete WCAG, hosted security, production deliverability or unconditional V1 release certification is claimed. The full original browser aggregate/Linux CI was not executed on this Windows host; the relevant V1 candidate, calendar, model, DOM, integrity and lifecycle checks are reported individually.

## Reproduce and roll back

Install the pinned development dependencies with `npm ci --ignore-scripts`. Run `npm run build`, `npm run check:build`, `node scripts/check-vendor-integrity.cjs`, `node scripts/verify-release.cjs`, `npm test`, `npm run test:dom`, `npm run test:calendar` and `npm run test:v1:candidate`. The latter now includes the four new connected-reading, presentation, zoned-editor and notes/sections browser suites. Browser tests can use `HV_CHROMIUM_PATH`; Windows importer tests accept `HV_PYTHON_PATH` for a real Python interpreter. DOM tests accept a `file:///` D3 module URL via `HV_D3_MODULE` on Windows. Offline upgrade tests require `HV_PREVIOUS_ROOT` pointing to the prior application source rebuilt with canonical byte tooling.

For a local preview, serve the repository with a static HTTP server and open its printed localhost URL. Import fictional fixtures only into a disposable browser origin/profile; do not copy private account data into previews. The downloadable source archive has no credentials, node_modules, test outputs, caches or Git internals.

Rollback is the previous static application rebuilt with a coherent manifest. Do not clear travel storage, account outboxes, private checkpoints or service-worker recovery to roll back a visual change. New note end dates and explicit fold-choice fields are additive; older readers must preserve unknown fields. There is no database migration or second record authority to reverse.
