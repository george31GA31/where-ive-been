# Entry-requirements data

`passport-index.js` is an imported, MIT-licensed snapshot of [imorte/passport-index-data](https://github.com/imorte/passport-index-data), published 17 February 2026 and retrieved 2 October 2026. It covers 199 passports and 39,402 routes and provides the default worldwide visa answer. It is planning information, not official government confirmation. Retrieval does not change the provider's update date.

`guidance.js` contains small, sourced official corrections and health conditions. Existing destination guidance was reviewed 2 October 2026; CTA and EU/EEA/Swiss short-visit rights were reviewed 3 October. Own-country citizenship handling precedes tourist rules. Applicable official corrections override provider data. Explicit `validFrom`/`validTo` periods control dated rules. Review deadlines affect the confidence label, not the underlying answer: an overdue correction is labelled reviewed rather than verified and does not silently revert to a conflicting matrix result. Undocumented historical checks display the latest dataset answer with a historical-scope note.

Only passport and destination are required. An omitted date means current/general requirements; optional trip context enhances the result. A longer stay, a special purpose or a residence permit adds a separate scope note instead of erasing the ordinary-passport short-visit answer. No unsupported residence-permit exemption is inferred. Health assessment is independent of visa status; entry certificates and recommended vaccinations are displayed separately. Missing documentation detail is not invented.

Refresh the dataset with `node scripts/update-entry-data.cjs /path/to/provider.json PROVIDER_UPDATED_DATE RETRIEVAL_DATE`. Reviewed corrections live outside the generated snapshot. Browser refreshes validate coverage before accepting a provider response and retain the bundled answer when a refresh fails. A refreshed response without version metadata retains an unknown provider update date; it is never marked officially verified. Review guidance separately; do not advance `checked` dates without reviewing the linked authority. Requirements are cached in memory by the entire input context and expire independently of user storage. There are no account migrations, new storage keys or database writes, and no paid API.

## Destination health guidance

`travelhealthpro.js` contains factual extracts from the [TravelHealthPro country directory](https://travelhealthpro.org.uk/countries) and its linked destination pages, retrieved 3 October 2026. The initial import covers all 262 directory destinations, 237 canonical source pages and 237 Herald country mappings. A redirect to broader advice retains that source scope; it does not create region-specific medical advice. `health-refresh.json` records successful, retained and unavailable sources. Missing destinations, including the Vatican and several small territories, remain unavailable rather than inheriting a neighbouring country's guidance.

TravelHealthPro / NaTHNaC content is Crown copyright and available under the [Open Government Licence v3.0](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/), as stated on the [source About page](https://travelhealthpro.org.uk/about). Attribution and a destination source link are displayed in every result. These extracts are planning information and do not replace the original guidance or a qualified medical consultation. No TravelHealthPro branding, design, scripts, personal data or medication dosing tables are imported.

Run `node scripts/update-health-data.cjs` to refresh the entire provider snapshot. The weekly `Refresh destination health guidance` workflow does this automatically, validates unit, DOM and browser regressions, commits only the two generated provider files, then requests a build using the existing GitHub Pages source. It never writes user records. Concurrent main changes cause the push to fail rather than merging unvalidated code. No new secret is needed; the workflow uses its scoped GitHub token.

The importer identifies itself, checks the current reuse licence and robots rules, follows permitted same-origin country redirects only, and makes one request at a time with a minimum 1.5-second gap. Source denials and rate limits stop the refresh. Network failures, unexpected identities or parser changes retain the destination's last successful data and original retrieval date. Less than 95% newly successful coverage rejects the complete refresh and leaves the bundle untouched. Each record retains its source URL, identifier, retrieval date, source status, certificate facts, vaccine groups, malaria risk-area statements and dated destination notices. No provider update date is invented. The UI labels retained or over-30-day guidance, and removes notices older than 90 days.

`health-destination-aliases.json` supplies exact naming exceptions and parent-scoped region aliases. Trip locations can select French Guiana, Hong Kong, Galápagos and other listed regions without changing the saved country or immigration destination. Ambiguous mixed regions use the wider country; the optional Health destination selector permits an explicit choice. Matching never uses edit-distance or loose fuzzy country names. `entry-health.js` returns defensive copies and fails independently of visa lookup. Existing reviewed certificate assessments and acknowledgement fingerprints are preserved; advisory vaccine disclosure cannot turn a visa-free result into a visa requirement.

The source DOM fixture in `tests/fixtures/travelhealthpro-india.html` is a reduced, attributed OGL extract from the India page retrieved on 3 October 2026. It exercises certificate qualifiers, real source categories and regional malaria parsing without making external requests in tests.
